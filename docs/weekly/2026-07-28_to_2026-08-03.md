#### 4. 长时程状态反馈优化

针对50,000轮策略XY漂移问题，建立`Tracking-Flat-DexEVT-State-Feedback-Long-Horizon-v0`任务，开展多阶段优化：

- A/B时域对照：5秒和10秒各500次更新。
- Stage 1：10秒时域继续1500次，加入直接参考关节位置保真奖励。
- Stage 2：20秒时域继续1500次。
- Stage 3：39.72秒全动作时域继续500次。
- 上述分支合计新增4500次4096环境更新。

优化原则：

- 保留原始动作约0.487 m的骨盆净XY位移，不增加“回到平台中心”或“固定机器人在原点”的奖励。
- actor从124维扩展到130维，新增骨盆位置误差`motion_anchor_pos_b`三维和骨盆线速度`base_lin_vel`三维。
- 到动作末帧后冻结参考，不再回绕到第0帧。
- 增加尾段、初始静止段和晚期恢复窗口诊断，避免全局均值掩盖局部失败。

#### 5. 选定最终策略并完成4/4严格验收

- 最终策略采用Stage 2相邻checkpoint插值：`0.75 × model_52000 + 0.25 × model_52499`。
- 名义seed 42和随机化seed 0/1/2共4种工况全部通过严格验收。
- 四次回放均为3972/3972帧、100%完成、无提前终止、无动作循环、全部数值有限。
- 四工况XY drift P95分别为0.1827、0.1986、0.2098和0.1482 m。
- 相比原50,000轮模型，四工况XY P95均值改善约77.2%，关节P95相比B-10s分支平均改善约31.1%。
- 正常速度视频为100 FPS、3972帧、39.72秒、1280×720，并通过完整解码验证。

#### 6. 当日技术决策与复盘

长时程优化结果说明，训练曲线稳定不等于完整动作回放一定更好。Stage 3虽然平均episode length和训练reward保持稳定，但严格回放只通过1/4，因此没有机械选择“iteration最大”的最后模型。最终采用相邻优质checkpoint权重插值，是基于相同网络结构、相同normalizer和四工况实测结果做出的选择。插值后的checkpoint用于推理和部署，不建议直接续训，因为其中保留的优化器状态来自B端点，已不再与插值权重严格一致。

当天还形成了一个重要工程原则：平台中心只用于安全边界检查，不应成为动作目标。Dance1参考本身包含约0.487 m的水平净位移，如果强制机器人固定在中心，会破坏原动作语义。最终策略的最大平台距离仍小于1 m，同时能跟随参考平移。因此“没有固定在中心”不是缺陷，而是忠实模仿原动作的预期表现；真正需要约束的是相对参考轨迹的XY误差和尾段恢复。

#### 4. 播放问题分类与处理结论

针对播放窗口中的现象，当天将问题分为三类处理。第一类是功能错误，例如策略没有加载、checkpoint维度不匹配或终止条件过早触发，需要结合终端堆栈和Hydra配置定位。第二类是视觉问题，例如彩色身体marker、相机距离过远、机器人在画面边缘以及录制没有覆盖机器人，这些不一定影响策略数值，但会影响人工验收。第三类是兼容性警告，例如`quat_rotate_inverse`即将弃用，它提示未来需要替换API，却不会直接导致当前回放失败。这样分类后，避免把黄色弃用提示误认为训练模型已经失效。

回放工作还明确了“完整动作”判定方式：不能只看窗口中机器人动了几秒，而要检查是否从第0帧连续执行到第3971帧、是否发生motion wrap、是否提前触发非timeout termination，以及视频是否完整解码。导出的ONNX和视频分别承担不同职责：ONNX用于部署推理，视频用于视觉确认，二者都不能代替逐步数值指标。当天结果证明10,000轮策略具备可导出、可加载和可播放的基本条件，但尚未完成MuJoCo真实状态反馈闭环验证。

## 四、问题、风险与后续建议

### 1. 130维模型尚未获得真实sim2sim状态反馈

当前xSIM虽然内部能够读取IMU位置传感器和线速度传感器，但现有`bodyctrl_msgs/Imu`消息只发布姿态、角速度和线加速度，没有把基座世界位置与线速度发送给`xmigcs_test`。参考值补齐只能用于接口联通和初步动作观察，不能替代训练时闭环反馈。

建议后续增加独立的ROS pose/twist消息，或者使用标准Odometry消息发布基座位置、姿态、线速度和角速度；部署端再按训练定义变换到骨盆坐标系，恢复真实的`motion_anchor_pos_b`和`base_lin_vel`。

### 2. 50,000轮模型和最终长时程模型需要区分

当前部署到`xmigcs_test`的50,000轮模型是124维无状态反馈模型。7月29日严格4/4通过的最终长时程策略是130维插值策略，位于`optimization_results/2026-07-29_dance1_long_horizon/final_policy/onnx/policy.onnx`，两者不是同一模型。后者若用于MuJoCo，同样需要解决真实基座状态发布问题。

### 3. 部署验收不能只看机器人是否动起来

后续应至少记录：完整帧数、是否提前终止、关节误差P95、身体误差P95、骨盆姿态误差P95、XY drift P95/最大值、尾段恢复以及数值有限性。建议沿用7月29日的名义seed加3个随机化seed协议。

### 4. 建议保留配置与模型的一一对应关系

模型文件名、YAML名称和训练run名称应明确包含动作、观测类型、环境数和iteration，例如：

`dance1_easy_link24_state_feedback_4096_iter10000.onnx`

不要只通过修改`num_obs`复用不兼容的YAML。每次部署前应读取ONNX输入形状和`observation_names`元数据，并检查关节名称、默认关节角、action scale、刚度和阻尼。
